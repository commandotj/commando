## 摘要

本RFC定义了Commando React双面板文件管理器的核心文件管理功能v1版本。基于对现有代码库的深入分析，梳理并规范化文件管理的关键功能模块，包括文件浏览、选择、操作、批量处理等核心能力，为后续版本迭代和功能扩展奠定基础。

## 背景

### 问题描述

Commando React作为一个现代化的双面板文件管理器，已经实现了基础的文件管理功能，但缺乏系统性的功能规范和架构设计文档。需要对现有功能进行梳理，定义v1版本的核心功能范围，为产品发展提供清晰的技术路线图。

### 现状分析

通过代码分析，当前系统已具备以下核心组件：

- 双面板界面：`SplitterLayout`实现可调节的双面板布局
- 文件浏览：`FilePane`组件提供文件列表展示和导航
- 设备管理：`DeviceBar`支持磁盘驱动器检测和切换
- 批量操作：`BatchCopyService`实现多文件复制功能
- 状态管理：基于Redux的集中式状态管理
- IPC通信：主进程与渲染进程间的文件操作通信

### 业务驱动

构建基于Electron + React + TypeScript的现代化双面板文件管理器，提供直观高效的文件管理体验。采用模块化架构设计，支持扩展和定制。

### 核心功能模块

#### 1. 双面板布局管理

**功能描述**：提供可调节的双面板界面，支持独立的文件浏览和操作

- 可调节面板宽度比例

**功能描述**：核心文件浏览功能，支持目录导航和文件展示

- 目录层级导航

### 技术架构

#### 新服务架构设计 (Updated 2025-01-14)

**服务架构概述**：
采用面向服务的架构(SOA)，每个服务处理特定的文件操作功能，通过@Service装饰器自动注册和管理IPC通道，共享工作线程池，使用标准通信协议。

```typescript
@Service({
    name: "FileService",
    version: "1.0.0",
    workerScript: "fileWorker.js",
    maxWorkers: 3,
})
class FileService implements BaseService {
    async handleCopy(event: IpcMainInvokeEvent, params: CopyParams) {
        return this.workerPool.execute("FileService", "copy", params);
    }
}
```

#### 服务通信协议

```typescript
interface WorkerMessage {
    id: string;
    type: "request" | "response" | "progress" | "error";
    operation: string;
    payload?: any;
    progress?: number;
    timestamp: number;
}
```

#### 数据流 (服务架构)

```
User Action → Component → Redux Action → IPC Channel → Service Registry →
Target Service → Worker Pool → Worker Thread → File System
     ▲                                                     │
     │◄──── Progress/Response ◄──── Worker Message ◄──────┘
```

### 服务架构设计详解

#### 核心服务设计

**1. 服务注册与发现**

- `@Service` 装饰器自动注册服务到 ServiceRegistry
- 自动绑定 IPC 通道到服务方法
- 支持服务版本管理和依赖注入

**2. 工作线程池管理**

- 共享线程池，支持多种操作类型
- 智能负载均衡和任务调度
- 自动故障恢复和重试机制

**3. 标准通信协议**

- 统一的 WorkerMessage 接口
- 支持请求/响应、进度更新、错误处理
- 消息ID追踪和超时管理

#### 服务实现模式

```typescript
// 服务基类
interface BaseService {
    initialize(): Promise<void>;
    cleanup(): Promise<void>;
    getMetadata(): ServiceMetadata;
}

// 服务装饰器用法
@Service({
    name: "CopyService",
    version: "1.0.0",
    workerScript: "copyWorker.js",
    maxWorkers: 2,
})
class CopyService implements BaseService {
    // 自动绑定到 'copy:file' IPC 通道
    async handleFile(event: IpcMainInvokeEvent, params: CopyParams) {
        return this.execute("copy-file", params);
    }

    // 自动绑定到 'copy:batch' IPC 通道
    async handleBatch(event: IpcMainInvokeEvent, params: BatchCopyParams) {
        return this.execute("copy-batch", params);
    }
}
```

#### 设计优势

**1. 关注分离**

- 每个服务专注单一职责
- 减少服务间耦合
- 便于单元测试和维护

**2. 自动化管理**

- 自动 IPC 通道绑定
- 自动服务生命周期管理
- 自动工作线程池分配

**3. 可扩展性**

- 新服务只需添加装饰器
- 支持动态服务注册
- 统一的错误处理和日志

**4. 性能优化**

- 共享线程池资源
- 智能任务调度
- 支持并发和队列管理
