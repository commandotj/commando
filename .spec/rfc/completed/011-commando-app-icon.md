## 摘要

本 RFC 提议为 Commando 文件夹同步工具制作新的卡通应用图标。图标使用两个软陶文件夹角色交接文件的构图，并以双向循环箭头明确同步语义。

本 RFC 只定义视觉资产、验证方法与非破坏落地顺序。不修改同步引擎、CLI、Wails IPC 或 React UI。

## 背景

### 问题描述

当前 `apps/desktop/build/appicon.png` 已使用蓝、黄文件夹与循环箭头，但玻璃质感、霓虹高光和细碎装饰过多。1024px 下效果华丽，缩到 Dock、任务栏与文件列表尺寸后，主体轮廓和同步含义变弱。

旧备份 `apps/desktop/build/appicon.png.bak` 仍是 Wails 标记，不能表达 Commando 产品用途。

### 现状分析

- 主图：`apps/desktop/build/appicon.png`，1024×1024 PNG。
- macOS：`apps/desktop/build/darwin/icons.icns`。
- Windows：`apps/desktop/build/windows/icon.ico`。
- iOS：`apps/desktop/build/ios/icon.png`。
- Icon Composer 源：`apps/desktop/build/appicon.icon/`，当前仍引用 Wails 矢量标记。

平台派生图标不应先于主图验收更新，否则一个未验证候选会同时污染多个平台资产。

### 业务驱动

图标需要一眼表达“友好、可靠的双向文件同步工具”，并在小尺寸下保持清楚。视觉升级必须避免影响现有程序行为。

## 目标

### 主要目标

- [x] 制作 1024×1024 的“文件交接队 / 软陶 3D”候选图。
- [x] 在 1024px、128px、32px 三种尺寸验证图标辨识度。
- [x] 候选通过审批前不覆盖现有主图。
- [x] 主图审批后，再独立更新 macOS、Windows 与 iOS 派生资产。

### 非目标

- 不修改应用名称、产品文案或 UI 主题。
- 不修改 Go、TypeScript、React 或 Wails 代码。
- 不设计完整品牌系统。
- 不添加启动画面、菜单栏图标或网站标志。

### 成功标准

1. 蓝色文件夹、橙色文件夹、中央文件、双向循环箭头四个元素清楚。
2. 图像无文字、字母、品牌缩写、水印或裁切。
3. 软陶材质统一，无玻璃感、强霓虹或彩虹溢光。
4. 32px 预览仍能被识别为文件夹同步工具。
5. 候选使用版本化文件保存，不覆盖当前 `appicon.png`。

## 提案

### 解决方案概述

采用已确认的 C1 方向：

- 左侧蓝色软陶文件夹角色。
- 右侧橙色软陶文件夹角色。
- 两个角色共同交接一张暖黄色文件。
- 青绿色双向循环箭头位于角色后方。
- 冷白到浅蓝低对比背景。
- 小眼睛与克制微笑，友好但不幼稚。

### 视觉结构

画布为 1024×1024 正方形。主体占中央约 70%，四周至少保留 15% 安全边距。

两个文件夹略微向中心倾斜。交接文件位于视觉中心。双向循环箭头必须形成完整闭环，但不能遮挡表情和交接文件。

阴影只用于分离层次。文件夹本体保持最大轮廓，角色手脚不得成为主要视觉元素。

### 色彩

- 左侧文件夹：天蓝到群青。
- 右侧文件夹：暖黄到橙色。
- 交接文件：奶油黄，少量珊瑚色线条。
- 循环箭头：青绿色。
- 背景：冷白到浅蓝。

禁止添加云朵、设备、闪电、齿轮、额外文件或装饰粒子。

### 生成流程

1. 使用内置图像生成工具生成单张 1024×1024 候选。
2. 将候选保存为 `apps/desktop/build/appicon-c1.png`。
3. 检查 1024px 原图的构图、边缘、文字与水印。
4. 生成 128px、32px 临时预览，仅用于验证。
5. 若存在一个主要问题，允许一次单点修订。
6. 用户批准候选后，才提出替换主图与重建平台资产的独立执行计划。

## 替代方案

### 方案 A：文件夹搭档

两个带表情文件夹被循环箭头包围。同步语义强，但缺少“交接文件”的故事焦点；小尺寸表情容易消失。

### 方案 B：同步传送门

两个文件夹围绕发光同步通道。轮廓最稳，但卡通角色感不足，与用户选择不符。

### 方案 C：文件交接队

两个文件夹角色共同交接文件，并保留双向循环箭头。故事感与同步语义平衡最好，因此选用。

## 影响分析

### 对现有系统的影响

候选阶段只新增 PNG 文件，不改变运行时行为。主图替换与平台资产重建必须在后续审批中单独执行。

### 兼容性分析

不影响 CLI、Go 核心、Wails 服务、React UI、用户配置或文件同步结果。现有 `appicon.png` 在候选审批前保持不变。

### 性能影响

无运行时性能影响。安装包体积变化应仅为图标编码差异。

## 风险评估

| 风险                       | 概率 | 影响 | 缓解措施                    |
| -------------------------- | ---- | ---- | --------------------------- |
| 小尺寸细节糊成一团         | 中   | 高   | 强制检查 128px 与 32px 预览 |
| 交接动作被误读为单向发送   | 中   | 中   | 保留完整双向循环箭头        |
| 生成结果出现文字或多余物体 | 中   | 中   | 明确负面约束并逐项检查      |
| 未批准候选覆盖正式图标     | 低   | 高   | 先保存 `appicon-c1.png`     |
| 派生平台图标与主图不一致   | 中   | 中   | 主图批准后统一重建          |

## 测试策略

### 自动检查

- 使用 `file` 或等价工具确认 PNG 尺寸与颜色格式。
- 检查候选文件存在且当前 `appicon.png` 哈希未改变。
- 生成 128px 与 32px 临时预览。

### 人工验收

- 1024px：检查构图、材质、文字、水印与边缘。
- 128px：检查角色、交接文件与循环箭头层级。
- 32px：检查是否仍能识别为双文件夹同步工具。

## 回滚

候选阶段无需回滚：删除未采用的版本化候选即可。正式替换阶段必须先保留现有主图哈希或备份，并在独立计划中说明恢复步骤。

## 后续工作

本 RFC 获批并完成候选审批后，可创建后续实施任务，统一重建平台派生图标。菜单栏单色图标与完整品牌系统不在本 RFC 范围内。
